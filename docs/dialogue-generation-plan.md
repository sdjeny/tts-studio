# LLM生成对白方案对比与实现

> 日期：2026-05-12
> 状态：测试中

---

## 一、问题

当前方案（幕规划+逐幕生成）存在：
- 对白碎片化，每条独立生成，缺乏上下文连贯
- 旁白和对话割裂
- 角色性格不够突出

---

## 二、方案对比

### 方案A：当前方案（幕规划+逐幕生成）

**流程**：
1. LLM规划幕结构 → `{"scenes":[...]}`
2. 逐幕调用LLM生成对白 → `{"dialogues":[{"character":"角色名","text":"对白","instruct":"情绪"}]}`
3. 角色匹配入库

**问题**：
- 每次只生成几条，循环调用，碎片化
- 旁白和对话分离
- 角色性格不连贯

### 方案B-2：一次性生成完整故事（推荐）

**流程**：
1. LLM一次性生成完整故事，纯文本
2. 每段标注 `[角色名]`，旁白也标 `[旁白]`
3. 括号标注情绪，如 `[小明]（沉声）...`
4. 后期解析文本，提取角色名、instruct、text
5. 角色匹配入库

**优点**：
- 故事连贯，有完整起承转合
- 旁白和对话自然融合
- 角色性格鲜明
- 字数和顺序完全自由

**测试结果（第3轮最佳）**：
- 字数：1085字（目标780，+39%，可接受）
- 旁白：19%（目标20%，符合）
- instruct：100%（括号情绪词完美提取）
- 故事完整，有探索、发现、悬念留到后续

**多轮测试对比（3轮）**：

| 排名 | 轮次 | 字数 | 偏差 | 旁白 | instruct | 得分 |
|------|------|------|------|------|---------|------|
| ★1 | 第3轮 | 1085 | +39% | 19% | 100% | 68.7 |
| 2 | 第1轮 | 1054 | +35% | 36% | 100% | 40.0 |
| 3 | 第2轮 | 0 | -100% | 0% | 0% | 0.0（LLM偶发错误） |

> 说明：字数和旁白占比都是"大约"值，允许LLM根据剧情需要灵活调整，不追求精确匹配。

## 四、上下文注入规则

### 前情提要
- **全部传入**，当前章之前的所有剧集摘要（不限制数量）
- 格式：`- 第X集：摘要内容`

### 后续规划
- **最多5章**，即当前章之后的5个剧集摘要（第N+1 ~ N+5集）
- 超过5章截断，只保留最近的5章
- 无后续章节时，标注"无（本章为最终章）"
- 格式：`- 第X集：摘要内容`

### 衔接要求（prompt）
```
前情提要：
- 第N集：xxx
- 第N+1集：xxx
（全部传入，不限数量）

后续规划：
- 第N+2集：xxx
- 第N+3集：xxx
（最多5章，超出截断）

要求：
- 本章内容必须承前启后，与前后章节自然衔接
- 如果有后续章节，本章不能提前消耗后续的关键情节或悬念
- 如果没有后续章节（最后一章），本章必须完整收尾，给出结局
```

## 五、可配置参数

| 参数 | 说明 | 默认值 | 示例 |
|------|------|--------|------|
| `target_duration_min` | 目标朗读时长（分钟） | 3 | 5 |
| `word_count` | 目标字数（自动计算或手动覆盖） | 分钟×260 | 780 |
| `narration_ratio` | 旁白占比（%） | 20 | 30 |
| `style` | 故事风格 | 白话叙事 | 悬疑/轻松/文言 |
| `temperature` | LLM温度 | 0.7 | 0.9 |

**字数计算**：`word_count = target_duration_min × 260`（可手动覆盖）

**旁白占比**：可配置，传入prompt如"旁白约占20%"

**风格**：传入prompt如"风格：悬疑，节奏紧凑"

> ⚠️ **注意**：字数、旁白占比、风格都是"大约"值，不要定死。LLM需要有自由度，过于精确的控制会导致输出呆板。prompt中用"约"、"大约"等措辞，允许LLM根据剧情需要灵活调整。

## 六、LLM输出格式

### 输出规则（prompt）
```
1. 每段开头用[]标注角色名，包括旁白也标[旁白]
2. 顺序和字数完全自由，根据剧情需要
3. 可以是旁白、独白、对话任意组合
4. 总字数约X字（根据朗读时间计算），允许±20%浮动
5. 故事完整，有起承转合
6. 对话符合角色性格
7. 可以根据剧情需要引入新角色
8. 输出纯文本，不要JSON
```

### 输出示例
```
[旁白] 夜色沉沉，雨后的街灯把路面映得斑驳。
[小明]（沉声）这纸张已经发黄，笔迹也带着淡淡的墨香。
[小红]（活泼）哎呀，明哥，这不就是冒险的开始吗！
[旁白] 小红的眼睛在灯光下闪闪发亮。
[小明]（谨慎）废弃灯塔？那是旧铁路旁的老建筑，已经半塌多年。
```

## 七、解析逻辑

### 正则提取
```python
import re

# 匹配 [角色名]（情绪）内容
# 或   [角色名] 内容
pattern = r'\[([^\]]+)\](?:\s*（([^）]+)）)?\s*(.*?)(?=\n\[|\Z)'
```

### 提取示例
| 原文 | 角色名 | instruct | text |
|------|--------|----------|------|
| `[旁白] 夜色沉沉...` | 旁白 | "" | 夜色沉沉... |
| `[小明]（沉声）这纸张...` | 小明 | 沉声 | 这纸张... |
| `[小红]（活泼）哎呀...` | 小红 | 活泼 | 哎呀... |
| `[小明] 你觉得呢？` | 小明 | "" | 你觉得呢？ |

### 入库流程
1. 解析文本 → `[{role, instruct, text}, ...]`
2. 旁白 → `character_id = ""` 或特殊处理
3. 其他角色 → `_resolve_char_id()` 匹配或创建
4. 调用 `add_dialogue()` 逐条入库
5. SSE推送进度

## 八、字数计算

- 正常语速：200-250字/分钟
- 快速：250-300字/分钟
- 慢速：150-200字/分钟

**公式**：`目标字数 = 朗读分钟数 × 每分钟字数`

示例：
- 3分钟 × 260字/分钟 = 780字
- 25分钟 × 260字/分钟 = 6500字
