# TTS 音色选择技术方案

## 概述

本方案实现了 edge-tts 音色的友好显示与数据存储分离，用户看到中文别名，系统存储真实音色ID。

## 核心设计原则

**显示别名，存储真值**
- 前端下拉框显示：友好的中文别名（如"晓晓 - 温柔女声"）
- 后端数据存储：真实的音色ID（如`zh-CN-XiaoxiaoNeural`）
- 数据交换：Gradio Dropdown 自动处理元组格式的 choices

```python
    allow_custom_value=False  # 不允许自定义，只能从列表选择

```

**Gradio 元组 choices 工作原理**：
- `choices=[("显示名", "真实值"), ...]`
- 用户看到的是"显示名"
- 组件返回的是"真实值"
- 完美实现显示与存储分离

### 3. 音色验证函数 (app/ui.py)

```python
def ensure_voice_in_choices(voice):
    """确保音色值在下拉框的 choices 中，如果不在则返回默认值"""
    from .config import VOICE_IDS  # 在函数内部导入
    
    if voice in VOICE_IDS:
        return voice
    
    # 如果不在列表中，尝试匹配相似的音色
    for vid in VOICE_IDS:
        if voice and voice.startswith(vid.split('-')[0] + '-' + vid.split('-')[1]):
            return vid
    
    # 否则返回默认值
    return "zh-CN-YunjianNeural"
```

**使用场景**：
- 加载工程文件时，确保保存的音色ID仍然有效
- 切换对白行时，正确显示对应的音色
- 处理旧工程文件中可能存在的无效音色ID

## 数据流

### 用户操作流程

```
1. 用户点击下拉框
   ↓
2. 看到中文别名列表（如"晓晓 - 温柔女声"）
   ↓
3. 用户选择"晓晓 - 温柔女声"
   ↓
4. Gradio 返回真实ID "zh-CN-XiaoxiaoNeural"
   ↓
5. 点击"应用属性"按钮
   ↓
6. 保存到 script_line.voice = "zh-CN-XiaoxiaoNeural"
   ↓
7. 保存到工程 JSON 文件
```

### 加载流程

```
1. 从 JSON 文件读取 voice = "zh-CN-XiaoxiaoNeural"
   ↓
2. 调用 ensure_voice_in_choices(voice)
   ↓
3. 检查是否在 VOICE_IDS 中
   ↓
4. 返回真实ID "zh-CN-XiaoxiaoNeural"
   ↓
5. Gradio Dropdown 自动匹配并显示"晓晓 - 温柔女声"
```

## 关键要点

### ✅ 优势

1. **用户体验友好**：中文别名易于理解和选择
2. **数据标准化**：存储标准音色ID，便于维护和迁移
3. **向后兼容**：通过 `ensure_voice_in_choices` 处理旧数据
4. **扩展性强**：新增音色只需修改配置文件

### ⚠️ 注意事项

1. **函数作用域问题**：
   - `ensure_voice_in_choices` 定义在 `build_ui()` 内部
   - 必须在函数内部导入 `VOICE_IDS`，不能依赖模块级导入
   - 原因：Python 闭包无法直接访问外层函数的局部变量

2. **Gradio 版本兼容性**：
   - 元组格式的 choices 在 Gradio 4.x+ 中支持良好
   - 确保 `requirements.txt` 中指定正确的 Gradio 版本

3. **音色ID 变更**：
   - 如果 edge-tts 更新音色ID，需要同步更新 `VOICE_OPTIONS`
   - 建议定期运行脚本获取最新音色列表

## 维护指南

### 添加新音色

1. 在 `app/config.py` 的 `VOICE_OPTIONS` 中添加新条目：
   ```python
   ("显示名称", "真实音色ID"),
   ```

2. `VOICE_IDS` 会自动更新（列表推导式）

3. 重启服务即可生效

```bash
async def get_voices():
```
